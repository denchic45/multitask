Архитектура планировщика (Scheduler)
=====================================

Планировщик управляет распределением процессорного времени между зелеными потоками. Переключение контекста осуществляется в пространстве пользователя без обращения к системным вызовам ядра ОС на каждую операцию уступки управления.

Режимы работы: 1:N и M:N
------------------------

Библиотека поддерживает две конфигурации среды выполнения:

* **1:N (однопоточный режим)**:
  все зеленые потоки исполняются в контексте одного системного потока ОС. Межпоточная синхронизация очередей не требуется.

* **M:N (многопоточный режим с воркерами)**:
  пул из ``M`` системных потоков ОС исполняет ``N`` зеленых потоков. Распределение нагрузки осуществляется между ядрами процессора.

Конечный автомат состояний потока
---------------------------------

Каждый поток находится строго в одном из пяти состояний:

* ``:created``: память под структуру и стек выделена, поток инициализирован, но еще не помещен в очередь выполнения.
* ``:runnable``: поток находится в очереди готовых к исполнению и ожидает выделения процессорного времени.
* ``:running``: код потока исполняется процессором в текущий момент.
* ``:waiting``: исполнение приостановлено до наступления события (таймер, ввод-вывод, примитив синхронизации или вызов ``thread-notify``).
* ``:dead``: исполнение завершено либо поток принудительно остановлен через ``thread-kill``.

Схема переходов состояний:

.. code-block:: text

   [ :created ] ---> [ :runnable ] <=== thread-yield ===> [ :running ] ---> [ :dead ]
                            ^                                    |
                            |                                    v
                            +==== наступление события ====+ [ :waiting ]

Структуры очередей
------------------

Планировщик использует следующие очереди:

1. **Очередь выполнения (Run Queue)**:
   содержит потоки в состоянии ``:runnable``. Диспетчер извлекает потоки из начала очереди по алгоритму FIFO *(TODO: фиксация конкретной структуры данных: например - двусвязный список*.

2. **Очереди ожидания (Wait Queues)**:
   каждый примитив синхронизации (мьютекс, условная переменная) содержит отдельную очередь заблокированных потоков. При наступлении события разблокировки поток переносится из очереди ожидания в Run Queue.

Алгоритм цикла планирования
---------------------------

Рабочий поток планировщика циклически выполняет следующие операции:

1. Извлечение первого готового потока из Run Queue.
2. Переключение контекста на выбранный поток.
3. Обработка состояния при возврате управления в планировщик: при вызове ``thread-yield`` поток возвращается в конец Run Queue со статусом ``:runnable``; при блокировке поток переводится в статус ``:waiting`` и добавляется в очередь ожидания; при завершении функции потока ему присваивается статус ``:dead``, фиксируется результат и разблокируются потоки, ожидающие в ``thread-join``.
4. Если Run Queue пуста: переход в режим ожидания системных событий ввода-вывода и таймеров (см. :doc:`io_and_timers`).
