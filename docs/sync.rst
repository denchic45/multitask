Примитивы синхронизации (Sync)
=================================

Необходимость синхронизации в зеленых потоках
--------------------------------------------

Хотя в чисто кооперативной однопоточной модели (1:N) переключение контекста происходит только в явных точках (например, при вызовах ввода-вывода или ``yield-task``), примитивы синхронизации необходимы по двум ключевым причинам:

1. **Многошаговые составные операции**: если логическая транзакция содержит операции ожидания (например, чтение нескольких пакетов или паузу), состояние разделяемого ресурса не должно быть искажено другими зелеными потоками.
2. **Многоядерное исполнение (M:N)**: при наличии нескольких рабочих потоков ОС разные зеленые потоки могут физически выполняться одновременно на разных ядрах CPU.

Мьютексы (Mutexes)
------------------

Мьютекс (структура ``mutex``) обеспечивает взаимное исключение при доступе к критической секции.

Функции работы с мьютексом:
* ``(make-mutex &key name)`` — создает новый мьютекс.
* ``(acquire-mutex mutex &key timeout)`` — переводит текущую задачу в ожидание владения мьютексом. При превышении времени ожидания сигнализируется ошибка ``timeout-error``.
* ``(release-mutex mutex)`` — освобождает мьютекс и пробуждает одну из ожидающих задач.

Макрос ``with-mutex``
~~~~~~~~~~~~~~~~~~~~~

Наиболее безопасным и идиоматичным способом захвата мьютекса является макрос ``with-mutex``. Он автоматически освобождает ресурс даже в случае возникновения исключений:

.. code-block:: common-lisp

   (defvar *shared-counter* 0)
   (defvar *lock* (multitask:make-mutex :name "counter-lock"))

   (multitask:with-runtime ()
     (multitask:spawn
      (lambda ()
        (multitask:with-mutex (*lock*)
          (incf *shared-counter*)))))

Условные переменные (Condition Variables)
-----------------------------------------

Условная переменная (структура ``condition-variable``) позволяет зеленым потокам переходить в режим ожидания до тех пор, пока другой поток не изменит разделяемое состояние и не пошлет сигнал уведомления.

Функции работы с CV:
* ``(make-condition-variable &key name)`` — создает новую условную переменную.
* ``(wait-condition-variable cv mutex &key timeout)`` — атомарно освобождает захваченный мьютекс и переводит задачу в состояние ``:waiting``. При получении сигнала мьютекс повторно захватывается перед возвратом.
* ``(notify-condition-variable cv)`` — возобновляет выполнение одного из ожидающих зеленых потоков.
* ``(notify-all-condition-variables cv)`` — возобновляет выполнение всех ожидающих на данной переменной потоков.

Пример: Паттерн "Производитель — Потребитель"
---------------------------------------------

.. code-block:: common-lisp

   (defvar *queue* nil)
   (defvar *lock* (multitask:make-mutex :name "queue-lock"))
   (defvar *has-items* (multitask:make-condition-variable :name "queue-cv"))

   ;; Потребитель (Consumer)
   (defun consumer ()
     (multitask:with-mutex (*lock*)
       (loop while (null *queue*) do
         (multitask:wait-condition-variable *has-items* *lock*))
       (let ((item (pop *queue*)))
         (format t "Извлечен элемент: ~a~%" item))))

   ;; Производитель (Producer)
   (defun producer (item)
     (multitask:with-mutex (*lock*)
       (push item *queue*)
       (multitask:notify-condition-variable *has-items*)))
