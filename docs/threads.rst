Задачи и зеленые потоки (Threads / Tasks)
===========================================

Понятие задачи (Task)
---------------------

В библиотеке **Multitask** базовой единицей многозадачности является **задача** (структура ``task``), также называемая зеленым потоком.

Каждая задача обладает:
* Уникальным числовым идентификатором (``task-id``).
* Символьным или строковым именем для отладки и мониторинга (``task-name``).
* Собственным независимым стеком вызовов фиксированного размера (``task-stack-size``).
* Текущим состоянием жизненного цикла (``task-state``).
* Результатом завершения (``task-result``).

Жизненный цикл и состояния задачи
---------------------------------

Задача может находиться в одном из следующих состояний:

.. list-table::
   :widths: 20 80
   :header-rows: 1

   * - Состояние
     - Описание
   * - ``:created``
     - Задача инициализирована, память под стек выделена, но задача еще не передана в очередь планировщика.
   * - ``:runnable``
     - Задача находится в очереди готовых к исполнению и ожидает выделения процессорного времени.
   * - ``:running``
     - Задача непосредственно выполняется процессором.
   * - ``:waiting``
     - Задача заблокирована в ожидании события (таймер, мьютекс, ввод-вывод).
   * - ``:dead``
     - Выполнение функции задачи завершено (успешно либо с ошибкой), либо задача была снята через ``kill-task``.

Схема переходов состояний:

.. code-block:: text

   [ :created ] ---> [ :runnable ] <==== yield-task ====> [ :running ] ---> [ :dead ]
                           ^                                    |
                           |                                    v
                           +===== событие готовности ====+ [ :waiting ]

Управление задачами
-------------------

Создание задачи: ``spawn``
~~~~~~~~~~~~~~~~~~~~~~~~~~

Функция ``spawn`` принимает функцию без аргументов (лямбду) и регистрирует ее как независимый зеленый поток:

.. code-block:: common-lisp

   (multitask:with-runtime ()
     (let ((my-task (multitask:spawn
                     (lambda ()
                       (format t "Привет из зеленого потока!~%")
                       100)
                     :name "worker"
                     :stack-size 65536))) ; 64 КБ стек
       ;; ...
       ))

Кооперативная уступка кванта: ``yield-task``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Поскольку планировщик является кооперативным, долго выполняющиеся вычисления должны периодически уступать процессор другим задачам с помощью ``yield-task``:

.. code-block:: common-lisp

   (multitask:spawn
    (lambda ()
      (loop for i from 1 to 5 do
        (format t "Шаг ~a~%" i)
        (multitask:yield-task))))

Ожидание завершения: ``join-task``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Функция ``join-task`` приостанавливает вызывающий зеленый поток до тех пор, пока целевая задача не завершится, и возвращает вычисленный результат:

.. code-block:: common-lisp

   (multitask:with-runtime ()
     (let ((calc-task (multitask:spawn
                       (lambda ()
                         (multitask:yield-task)
                         (* 6 7)))))
       (let ((answer (multitask:join-task calc-task :timeout 2.0)))
         (format t "Ответ: ~a~%" answer)))) ; 42

Принудительная остановка: ``kill-task``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Функция ``kill-task`` переводит задачу в состояние ``:dead`` и прерывает ее выполнение:

.. code-block:: common-lisp

   (multitask:kill-task some-task)

Текущая задача и проверка активности
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* ``(current-task)`` — возвращает структуру ``task``, исполняющуюся в настоящий момент.
* ``(task-alive-p task)`` — возвращает ``T``, если задача еще не завершилась (находится в состояниях ``:created``, ``:runnable``, ``:running`` или ``:waiting``).
