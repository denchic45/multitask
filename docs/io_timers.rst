Таймеры и операции ввода-вывода (I/O & Timers)
================================================

Проблема блокирующих вызовов в зеленых потоках
----------------------------------------------

Стандартный вызов ``(cl:sleep 1.0)`` или чтение из блокирующего сокета приводит к тому, что операционная система переводит весь нативный системный поток (OS thread) в режим ожидания.

В среде зеленых потоков это недопустимо:
* Блокировка системного потока останавливает выполнение **всех** зеленых потоков, назначенных на этот рабочий воркер.
* Поэтому все операции сна и ввода-вывода должны быть **кооперативными** и неблокирующими на уровне ядра ОС.

Неблокирующий сон: ``task-sleep``
---------------------------------

Функция ``task-sleep`` приостанавливает выполнение только текущего зеленого потока на указанное количество секунд:

.. code-block:: common-lisp

   (multitask:with-runtime ()
     (multitask:spawn
      (lambda ()
        (format t "Засыпаем на 0.5 секунды...~%")
        (multitask:task-sleep 0.5)
        (format t "Проснулись!~%"))))

Механизм работы в планировщике:
1. Текущая задача переводится в состояние ``:waiting``.
2. Планировщик добавляет задачу в таймерную очередь (обычно двоичная куча или красно-черное дерево дедлайнов).
3. Рабочий поток переключается на следующую готовую задачу из очереди ``:runnable``.
4. При наступлении дедлайна планировщик переводит задачу обратно в статус ``:runnable``.

Асинхронное ожидание ввода-вывода: ``wait-fd-read`` и ``wait-fd-write``
-----------------------------------------------------------------------

Для взаимодействия с сетью (сокетами) и файловыми дескрипторами библиотека предоставляет примитивы кооперативного ожидания готовности:

* ``(wait-fd-read fd &key timeout)`` — переводит задачу в состояние ожидания, пока в дескрипторе ``fd`` не появятся данные для чтения.
* ``(wait-fd-write fd &key timeout)`` — переводит задачу в состояние ожидания возможности записи в дескриптор ``fd`` без блокировки.

Пример сетевого чтения (псевдокод):

.. code-block:: common-lisp

   (defun async-read-bytes (socket-fd buffer)
     ;; Ждем, пока ядро уведомит о поступлении данных
     (multitask:wait-fd-read socket-fd :timeout 5.0)
     ;; Теперь чтение гарантированно не заблокирует поток
     (read-sequence buffer socket-stream))

Интеграция с циклом событий (Event Loop)
----------------------------------------

Планировщик объединяет таймеры и события I/O в единый мультиплексирующий цикл:

.. code-block:: text

   +-----------------------------------------------------------+
   |                        Event Loop                         |
   |                                                           |
   | 1. Опрос epoll/kqueue с таймаутом до ближайшего таймера. |
   | 2. Пробуждение задач, чьи файловые дескрипторы готовы.    |
   | 3. Пробуждение задач, чьи таймеры истекли.                |
   | 4. Исполнение задач из очереди Run Queue (кванты времени).|
   +-----------------------------------------------------------+
